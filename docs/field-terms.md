# 현장 용어·은어 데이터 (방침·현재 구조·조사 기록)

담당: 장태웅 (2026-10-23 다른 팀원에게서 이전받음). 이 문서가 현장 용어 데이터 작업의 기준이다.

## 0. 결정 (2026-10-23, 사용자)

**언어별 데이터셋을 처음부터 만들지 않고, "은어 → 표준 한국어" 데이터를 중심에 둔다.**

- 은어(데스라·아시바·공구리 등)를 표준 한국어 뜻으로 알려 주면, 번역 모델(gpt-realtime-2.1)이 표준어를 각 언어로 옮기는 것은 대체로 잘한다는 판단. 이렇게 하면 zh·ru·uz 도 언어별 데이터 없이 은어 지원을 받는다 (지금은 vi 외 0건).
- 언어별 데이터는 **필요한 곳에만** 넣는다:
  1. **검증 문장**(긴급·안전 문장): 공식 번역을 그대로 쓰게 하는 장치라 언어별 번역이 필요 (예: 고용노동부 다국어 안전표지).
  2. **실측에서 모델이 틀리는 용어**: 표준어로 알려 줘도 오역·엉뚱한 선택이 나오는 단어만 언어별로 고정.
- 뜻이 문맥마다 다른 은어(다마·빠꾸·조지다·가라 등)는 표준어 하나로 바꾸지 않는다 → 지금처럼 "문맥에 따라" 규칙을 모델에 넘긴다.
- 처음 계획(중국어 은어 50개를 먼저 다 번역)은 이 결정으로 **취소**. 50개 중국어 초안은 실측 비교용으로만 남긴다 (5절).
- "표준어만 알려 주면 충분하다"는 것은 **아직 측정 전 추정**이다 → 4절 ②에서 실측으로 확인한다.

## 1. 지금 용어집이 통역에 반영되는 방식 (2026-10-23 코드 기준)

데이터: `server/data/legacy-workplace/` (원본 저장소 복사본, 수정하지 않음 — `SOURCE.md`). `LegacyWorkplaceAdapter` 가 5개 파일을 읽어 **용어 사전(lexicon)** 과 **검증 문장(phrases)** 으로 합친다. 같은 기준 표현은 하나로 합치고 먼저 읽은 번역이 우선, 빈 언어만 뒤 파일로 채운다.

- 용어 1개 = 기준 표현(canonical) + 변형(variants) + 받아쓰기 오인식형(asrCorrections) + 언어별 번역 + 뜻(meaning) + 번역 규칙(rule) + 위험도
- 은어 항목은 **기준 표현이 은어 자체**("아시바")이고, 표준어("비계")는 `translate_as_ko`·뜻에만 있다 → 문장 속 "아시바" 가 "비계" 로 바뀌지는 않는다
- 번역이 있는 언어: **vi 만**. 검증 문장 580개(긴급 160 + 일반 420)도 vi 만

### ① 문장 단위 통역 (일괄 지시·대화·문장 단위 통화) — 문장마다 맞춤
`messaging/pipeline.ts` → `DomainProcessor.process` → `buildContext` → `realtimeTranslator.buildInstructions`
1. 받아쓰기(gpt-4o-transcribe): 용어 힌트 **안 씀** (10-14 측정에서 오히려 나빠짐, `engine/domain/transcriptionHints.ts`)
2. 받아쓴 글에서 용어 감지 + 자동 보정: 변형·오인식형 → 기준 표현 ("대수라" → "데스라")
3. 번역 지시문에 **이번 문장에서 찾은 용어만** 최대 12개: `원문 → 대상 언어 번역: 뜻; 규칙`. 대상 언어 번역이 없으면 `원문: 뜻; 규칙` (지금 ko→zh·ru·uz)
4. 문장 전체가 검증 문장과 같으면(문장부호·공백 무시) "이 번역 그대로" 지시
→ zh 번역이 없어도 **뜻·규칙은 전달**된다

### ② 스트리밍 통화 (1:1 실시간) — 통화 시작 때 언어 쌍 기준으로 고정
`streamHub.ts` → `DomainProcessor.streamGlossary` → `streaming/engine.ts buildStreamInstructions`
1. 음성이 OpenAI 로 바로 가서 번역 전에 문장을 볼 수 없다 → 미리 넣는 용어집만 가능
2. **원문·대상 언어 표현이 둘 다 있는 용어만**, 위험도 순(critical → high 안전 분야 → high 핵심 → …) 최대 110개 + 검증 문장 12개. 글자 수 때문에 **뜻·규칙은 안 넣음**
3. 지시문 앞쪽에 고정 (OpenAI 프롬프트 캐시 유지). 전체 4,500자 상한 (`STREAM_INSTRUCTIONS_MAX_CHARS`)
4. 전사 세션(gpt-live-transcribe) keywords: 용어집 원문 쪽 단어 최대 50개
5. 턴이 끝난 뒤 원문 보정은 DB 기록용 (통역에는 영향 없음)

### 언어 쌍별 상태 (10-23 7절 반영 전 → 후)

| 언어 쌍 | 문장 단위 | 스트리밍 |
|---|---|---|
| ko↔vi | 용어 + 번역 + 뜻 + 검증 문장 | 용어 110 + 문장 12 + 키워드 → **+ 은어 뜻 20** |
| ko→zh·uz | 용어의 뜻·규칙만 → **+ 은어 표준어 뜻, 안전표지 검증 문장** | 용어 0·문장 0 → **은어 뜻 60 + 안전표지 문장 12** (키워드는 0 그대로) |
| ko→ru | 뜻·규칙만 → **+ 은어 표준어 뜻** | 0 → **은어 뜻 60** (러시아어 안전표지 없음) |
| zh·uz·vi → 다른 언어 | — | 안전표지 문장 12 (zh↔vi↔uz 서로) |

- 공단 CSV 5,218–5,612행 근처의 건설 일본어 묶음(약 300개) 중 사람이 고른 목록(`ACCEPT`)만. 첫 칸 = 은어, 나머지 한글 칸 = 표준어(최대 3개)
- **뺀 것**: 일상어와 겹치는 말 — 한국어는 띄어쓰기 경계 없이 글자열로 찾으므로 "사이·조기·지리·구이·도마·데마·유가·신나·우라·데코(데코레이션)" 등은 일상 문장에서 잘못 감지된다. 건설과 무관한 것(나까마·가오다시 등), 뜻이 없는 것(한빠)
- **철자 변형만 variants 에** (노가대·도가다, 메꾸라시·매꾸라이, 스덴·스뎅 등). **표준어는 variants 에 넣지 않는다** — variants 는 은어(기준 표현)로 "보정"되므로 "비계" 가 "아시바" 로 바뀐다. 일상어 철자도 같은 이유로 뺐다("세면" → "세멘" 이 되므로)
- 위험도: 안전과 직접 관련된 21개만 high/critical (데스리·하이바(안전모)·도지나(주상 안전벨트)·우마(말비계)·노보리(비계다리)·스지까이(가새)·도도메/야마도메(흙막이)·쿠사리·후쿠·도란스·브레까 등), 나머지 normal
- 기존 항목과 겹치면: 기존 뜻·번역·표준어(`translate_as_ko`)가 우선, 공단 쪽은 철자 변형만 더해진다. 대체 항목(데스라·아나방)만 다른 파일의 같은 기준 표현을 **모두 무시**(베트남어 파일의 "데스라 → lan can" 포함)

### 7-3. 코드 변경

### 7-4. 발견한 기존 문제 → ✅ 해결 (2026-10-23, 사용자 결정: (나) 먼저 + (가) 정리)
원본 seed 가 **표준어를 은어의 변형으로** 넣어 두어서, 문장 단위 통역에서 번역 전에 표준어가 은어로 "보정"된다. 일상 문장 30개로 확인 (공단 은어 210개로 인한 잘못된 감지는 0건):

| 말한 문장 | 번역기에 들어가는 글 |
|---|---|
| 우리 반장님 어디 계세요 | 우리 **오야지**님 **어디입니까** 계세요 |
| 가로로 놓으세요 | **요코**로 놓으세요 |
| 어디가 아파요 | **어디입니까**가 아파요 |
| 천천히 하세요 | **천천히 말해 주세요** 하세요 |
| 점심은 현장 식당에서 먹어요 | 점심은 **함바**에서 먹어요 |

- 표준어가 은어 변형으로 들어간 것 51개 (해체→바라시, 준비→단도리, 콘크리트→공구리, 마감→시마이, 경사→고바이 …) + seed 문장형 용어의 변형(어디→어디입니까, 천천히→천천히 말해 주세요). "비계·콘크리트" 처럼 다른 항목의 기준 표현이기도 한 말은 기준 표현이 우선이라 바뀌지 않는다
- 0절 방침(은어 → 표준어)과 반대 방향이고 번역 품질을 떨어뜨린다
- **(나) 적용**: 보정(글 바꾸기)은 받아쓰기 오인식형(asr)만 (`domainProcessor.ts shouldCorrect`). 변형(variant)은 감지만 하고, 번역 문맥에는 문장에 실제로 쓰인 표현으로 넣는다 (`- 데스리 → lan can`). 오인식형 보정(대수라 → 데스라, 아씨봐 → 아시바)은 그대로
- **(가) 적용**: 어댑터가 변형 목록에서 감지 잡음을 뺀다 (`legacyWorkplaceAdapter.ts cleanVariants`) — ① 은어 항목의 변형 중 그 은어의 표준어 뜻에 든 말(띄어쓰기 무시, 59개: 해체·가로·반장·준비·콘크리트·현장식당 …) ② 문장형 용어(…니까/…세요/…요)의 짧은 꼴(어디·언제·누구·천천히). 줄임말(톱→톱날, 타워→타워크레인 등)과 다른 항목의 기준 표현과 같은 변형(효과 없음)은 둔다. 변형 901 → 830개
- 결과: 위 일상 문장 30개 중 **바뀌는 문장 0개** (전: 7개). 남은 감지는 실제 용어(안전모·크레인·용접 등)와 "반장 → 관리자"(seed 동의어) 정도
- 남은 잡음(필요하면 나중에): seed 은어 변형에 남은 표준 구절 약 360개 중 일부(카트→구루마, 대충→가라, 처리하다→조지다, 막일→노가다 등)는 감지만 되어 엉뚱한 용어 설명이 붙을 수 있다. 자동 판별이 어려워 사람이 골라야 한다

## 8. 스트리밍 개선 실험: 턴 용어 → 은어 목록 확대 (2026-10-24, 사용자 승인, 실제 OpenAI $0.407, 누적 $1.157)

### 8-1. 실험한 것 — 말하는 도중 자막에서 이번 턴 은어를 찾아 번역에 넣기 (`turnTerms`)
- 엔진 옵션 `RealtimeStreamOptions.turnTerms` (`off`·`update`·`create`, **기본 off — 지금 서버는 쓰지 않는다**) + `StreamOpenOptions.turnTerms`(전사 조각 → 이번 턴 용어 함수). 턴 용어는 지시문 **맨 끝**(`Workplace terms heard in the current turn …`)이라 캐시는 그대로

|---|---|---|---|
| off (은어 60개 미리) | 2 | 2 | 3,932ms |
| update | 1 | 2 | 3,385ms (턴 밀림 1번) |
| create | 3 | 2 | 4,502ms |

- 판단: 자막이 은어를 제대로 받아쓰기 전에는 쓰지 않는다. 코드는 기본 off 로 남겨 두고, 받아쓰기가 좋아지면(아래 8-3) 같은 스크립트로 다시 잰다
