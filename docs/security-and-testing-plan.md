# 보안 · 안정성 · 테스트 계획

## 1. 보안

| 항목 | 방안 |
|---|---|
| 인증 | Supabase Auth (이메일 + 비밀번호). 앱은 Supabase 세션을 SecureStore에 보관하고 자동 갱신 |
| 토큰 검증 | API 서버와 소켓 핸드셰이크에서 Supabase JWKS로 서명·만료·`aud` 검증 (`jose`) |
| 비밀번호 재설정 | Supabase 재설정 메일 + 앱 딥링크 |
| 권한 | 모든 현장 리소스 접근 시 DB의 active 멤버십 확인. 관리자 전용 기능은 role 확인 |
| 현장 간 격리 | 모든 조회 쿼리에 `site_id` 조건과 멤버십 조인. 다른 현장 리소스 요청은 404 |
| 소켓 | 방 참여는 서버만 수행. 메시지는 수신자별 `user:` 방으로만 발행. 멤버 제외 시 즉시 방 제거 |
| DB 노출 차단 | DB는 로컬 Postgres로 서버만 접근. Supabase에는 데이터를 저장하지 않음 |
| 비밀키 | `OPENAI_API_KEY`, DB URL은 서버 `.env`(권한 600)에만. 앱에는 Supabase anon key만 |
| 비용 | OpenAI 호출은 BudgetGuard를 거쳐 $5 한도 초과 시 거부 |
| 입력 검증 | zod (REST 바디·쿼리, 소켓 페이로드). 음성 업로드 크기·길이·MIME 제한 |
| 가입 코드 | 8자리 무작위, 만료·횟수 제한·폐기, 입력 속도 제한, 승인 필수 |
| 속도 제한 | `express-rate-limit` (사용자·IP 기준) |
| 로그 | 토큰, 이메일, 메시지 본문은 로그에 남기지 않음 (메시지 id만) |
| 음성 파일 | 서버 로컬 디스크. API에서 권한 확인 후에만 전달 |

## 2. 안정성

| 상황 | 대응 |
|---|---|
| 네트워크 끊김 | 소켓 자동 재연결 + `/sync` 동기화 + 수신 확인 재전송 |
| 중복 요청 | `UNIQUE(sender_id, client_message_id)`, ack·complete 멱등 |
| 메시지 순서 | 서버 `seq` 기준 정렬 |
| OpenAI 장애·타임아웃 | 언어별 최대 2회 재시도(지수 백오프), 이후 `failed` + 수동 재시도 |
| 부분 실패 | 언어 단위로 격리. 다른 언어 수신자는 정상 전달 |
| 서버 재시작 | 시작 시 멈춘 `pending`/`processing` 번역 재등록, 클라이언트에 `sync:required` |
| 노이즈 필터 플러그인 오류 | 원본 오디오로 진행 + 경고 로그 |
| 동시성 | Realtime 세션 동시 수 제한, 조건부 UPDATE로 이중 처리 방지 |

## 3. 운영 최소 항목

- 구조화 로그(pino): 요청 id, 메시지 id, 단계별 지연(디코딩·필터·STT·특화 처리·번역·저장)
- OpenAI 호출 수와 모델별 사용량 로그 (비용 추정용)
- Prisma migrate로 스키마 관리, 개발/운영 Supabase 프로젝트 분리

## 4. 테스트 전략

| 계층 | 도구 | 범위 |
|---|---|---|
| 단위 | Vitest | 현장 특화 처리(감지·보정·컨텍스트), 데이터셋 어댑터 변환, 비용 한도, 상태 전이, 권한 판정, 가입 코드 생성 |
| API 통합 | Vitest + supertest + 테스트용 임시 Postgres(embedded-postgres, 테스트마다 생성·삭제) | 현장·가입·멤버·대화·메시지·지시 API, DB 제약 |
| 소켓 통합 | socket.io-client | 인증 거부, 구독 권한, 대상 외 노출 없음, 제외 시 차단, 재연결 동기화 |
| 파이프라인 | `FakeTranslator`, `FakeStt` (지연·실패 주입) | 언어별 팬아웃, 부분 실패, 재시도, 재시작 복구 |
| 외부 연동 (수동, 비용 발생) | 스크립트 | 실제 `gpt-realtime-2`·STT 호출로 5개 언어 샘플 번역, 지연 측정 |
| 모바일 | Jest + React Native Testing Library | 전송 대기열, 소켓 이벤트 → 캐시 반영 로직 |
| 실기기 | 체크리스트 | Android 2대(관리자·구성원) + 블루투스 헤드셋 |

인증은 테스트에서 테스트용 키 쌍으로 서명한 JWT를 사용해 Supabase 없이 실행한다 (JWKS 검증부를 주입 가능하게 구성).
