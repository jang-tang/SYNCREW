# 현장 용어 통역 정확도·지연 측정 (2026-10-24)

1:1 통화 스트리밍 통역(실제 OpenAI, `gpt-realtime-2.1`)에 현장 문장 200개를 한국어 → 베트남어, 한국어 → 중국어로 각각 돌려,
**뜻이 맞게 통역됐는지**와 **말이 끝나고 첫 통역 음성이 나오기까지 걸린 시간**을 쟀다.
문장별 결과는 [`field-accuracy-results.csv`](field-accuracy-results.csv) (400행)에 있다.

## 1. 결과 요약 (발표용)

|---|---|---|---|
| **정확도** (뜻이 맞게 통역된 문장) | 178 / 200 = **89.0%** | 180 / 200 = **90.0%** | 358 / 400 = **89.5%** |
| **지연 중앙값** (말 끝 → 첫 통역 음성) | **2.01초** | **1.83초** | **1.91초** |
| 지연 90% 값 | 2.53초 | 2.21초 | 2.39초 |
| 3초 안에 나온 비율 | 96% | 98% | 97% |

갈래별 정확도:

| 문장 갈래 | 문장 수 | 베트남어 | 중국어 |
|---|---|---|---|
| 현장 은어 (일본어에서 온 말: 아시바·데마찌·공구리 등) | 100 | 89% | 91% |

발표에 쓸 문장 예: "현장 문장 400개(베트남어·중국어 각 200개) 실측 — 통역 정확도 89.5%, 말이 끝나고 통역 음성이 나오기까지 평균 약 1.9초(중앙값)".
각주로 4절의 측정 조건(합성 음성, 서버 기준 지연, 채점자)을 함께 적을 것.

## 2. 측정 방법

- **문장 200개** (`server/scripts/field-accuracy-sentences.json`, 측정용으로 새로 씀)
  - 은어 100: 안전보건공단 은어 자료(`server/data/legacy-workplace/supplement/kosha_slang.json`)에서 위험도 높은 은어 전부 + 자주 쓰는 은어. 문장마다 표준 한국어 정답 뜻(`meaning`)을 적음
  - 표준 용어 60: 추락·끼임·전기·화재·중장비 안전 지시
  - 숫자·시간·지시 40: 시각·층·수량·길이·온도 + 긴급("멈춰! 위에서 떨어진다!") + 일상 응답
- **음성**: macOS 한국어 합성 음성(Yuna)으로 만든 파일을 실제 휴대폰처럼 100ms 조각으로, 실시간 속도로 보냄 (문장당 평균 2.3초)
- **통역**: 실제 통화와 같은 코드(`RealtimeStreamEngine`) — 은어 뜻 용어집·받아쓰기 keywords·직전 2문장 문맥·말 없는 턴 버리기(2026-10-24 수정) 포함. 한 세션에서 200문장을 차례로 (`server/scripts/field-accuracy.ts`)
- **지연**: 마지막 말소리가 끝난 순간(파일 끝 무음 제외) → 첫 통역 음성이 서버에 도착한 순간. 말이 끝났다고 판단하는 무음 0.5초를 포함한다
- **채점**: 번역문을 정답 뜻과 비교해 "뜻이 맞게 전달됐는가"로 맞음(1)/틀림(0). 핵심 용어가 틀리거나 빠지면 문장의 나머지가 맞아도 틀림, 없는 말을 덧붙여도 틀림. 표현이 달라도 뜻이 같으면 맞음 (예: 데마찌 → "chờ việc"(일 기다림)). 채점은 Claude(AI)가 했고, 틀린 문장마다 이유를 CSV `note` 열에 적었다
- **비용**: 400문장 약 $3.84 (문장당 약 $0.0095)

## 3. 틀린 문장 (42개) — 어떤 실수였나

| 유형 | 베트남어 | 중국어 | 예 |
|---|---|---|---|
| 소리를 잘못 알아들음 (받아쓰기도 같은 쪽으로 틀림) | 14 | 12 | 슬래브 → 슬리브, "퇴근은 5시 반" → 최근엔 → "지금은 5시 반", "이 미터 이상" → 숫자 빠짐(중국어는 "1미터"), 우마 → 구마 → 사다리·운하, 마에가리 → "Mycari", 신호하세요 → 신고하세요 |
| 소리는 맞게 들었지만 용어를 다른 말로 옮김 | 7 | 7 | 비계 → 기계(máy), 훅 해지장치(빠짐 방지) → 풀림 장치, 비계공(도비) → 사람 이름, 자재 쌓지 마 → 주차하지 마, 슬래브 → 套管(슬리브) |
| 말 빠짐 | 1 | 1 | 1동 빠짐, 3시 반 → 3시 |
| 합계 | 22 | 20 | |

"소리를 잘못 알아들음" 일부는 합성 음성의 발음 탓일 수 있다 (예: "빠꾸할 때" → "작업할 때").

안전과 직결된 오역은 이렇다. 그 밖의 오역은 대부분 공구·자재 이름이다.
- "높이 2미터 이상 안전대" → 숫자 빠짐 / 1미터 (2건)
- "비계 위에서 안전대" → "기계 위에서" (2건, 베트남어는 받아쓰기 "난간대", 중국어는 받아쓰기 "기계")
- "고압선 근처 크레인 금지" → "압력관 근처" (베트남어 1건)

**받아쓰기는 틀려도 통역은 맞는 경우가 많다.** 은어 문장에서 받아쓰기가 은어를 틀린 경우가 베트남어 72문장, 중국어 52문장이었다. 그중 베트남어 64문장(89%), 중국어 45문장(87%)은 통역이 맞았다. 통역 모델이 글이 아니라 소리를 직접 듣기 때문이다. 다만 말한 사람 화면의 자막(받아쓰기)에는 은어가 틀리게 보인다.

## 4. 측정 조건과 한계 (각주에 쓸 것)

- **사람 목소리가 아니라 합성 음성**이고, 조용한 상태다. 실제 현장(소음·사투리·빠른 말)에서는 받아쓰기·통역 정확도가 더 낮을 수 있다
- **지연은 서버 기준**이다. 서버에서 상대 휴대폰까지 보내는 시간과 재생이 시작되는 시간(같은 Wi-Fi 기준 보통 0.1–0.3초)은 빠져 있다. 시드니 서버를 쓰면 인터넷 왕복 시간이 더해진다
- **은어 100개는 모두 미리 넣은 용어집 안의 은어**다. 용어집에 없는 은어의 정확도는 이보다 낮다 (`docs/field-terms.md` 8절: 목록 밖 은어 7개 중 2개만 맞음)
- 채점자는 AI(Claude) 1명이다. 베트남어·중국어 원어민 검수는 하지 않았다
- 1회 측정이다. 같은 문장을 다시 돌리면 몇 문장은 결과가 달라질 수 있다
- 지연이 5초를 넘은 문장이 베트남어에서 5개 있었다 (최대 10.4초: s012·s068). 원인은 확인하지 않았다. 중앙값·90% 값에는 거의 영향이 없다

## 7. 실측 오역 단어 보강 (2026-10-24, 비용 0)

- 확인한 것: **ko→zh 스트리밍 용어집에 표준 용어가 0개**였다 (데이터에 중국어 번역이 없음). ko→vi 는 110개가 차 있었지만 슬래브·고압선·화기 작업이 없었다
- `server/data/legacy-workplace/supplement/measured_terms.json`: 이번 측정에서 틀리게 옮겨진 표준 용어 + 헷갈린 말 12개에 vi·zh 번역 (슬래브·슬리브·비계·안전대·훅 해지장치·고압선·낙하물 방지망·화기 작업·신호수·비계공·말비계·멍에). "언어별 번역은 검증 문장·실측 오역 단어만" 결정(`docs/field-terms.md` 0절)에 맞춘 것. 번역은 Claude 작성, 원어민 검수 전
  - 다른 데이터보다 먼저 읽어 번역이 우선하고, 용어집 맨 앞에 둔다 (`domainProcessor.ts` `glossaryGroup`). 용어 상한 110 → **125** (사용자 허락, 기존 vi 용어가 밀려나지 않게)
- 은어 뜻: 데스라 "출력 인원" → "오늘 출근한 작업 인원(출력 인원)", 마에가리 "가불" → "가불(월급을 미리 받는 돈)" (`kosha_slang.json`, `scripts/build-kosha-slang.ts` STANDARD_FIX)
- 한계: **슬래브는 고쳐지지 않았다** — 받아쓰기부터 "슬리브"로 들려서 (합성 음성 발음), 용어집으로는 못 고친다. 사람 목소리로 다시 볼 것

## 8. 지연 단축 설정 비교 (2026-10-24, $2.55)

같은 50문장(200문장 중 4개마다 1개, 갈래 비율 유지)을 세 설정 × vi·zh 로 **동시에** 돌렸다 (`--every 4 --label …`, 7절 보강 포함).

**측정 문제**: 6개 측정을 동시에 돌리자 모두 13–14번째 문장부터 같은 시각에 번역이 비어(EMPTY) 300턴 중 97턴이 실패했다. 설정과 무관하게 같은 때 시작돼 **OpenAI 분당 사용량 한도(rate limit)에 걸린 것으로 보인다** (오류 내용은 기록하지 못함 — 엔진이 실패한 response.done 의 이유를 남기지 않는다). 그래서 6개가 모두 정상이던 앞 13문장 × 2언어 = 26문장씩으로만 비교했다:

| 설정 | 지연 중앙값 | 90% 값 | 평균 | 맞은 문장 (26개 중) |
|---|---|---|---|---|
| A 지금 (무음 500ms, 추론 low) | 2.15초 | 2.99초 | 2.53초 | 19 |
| B 무음 350ms | 1.91초 | 2.46초 | 2.03초 | 20 |
| C 무음 350ms + 추론 minimal | **1.71초** | **1.93초** | **1.75초** | **22** |

- C 가 중앙값 약 0.45초 빠르고(무음 단축 약 0.24초 + 추론 minimal 약 0.2초), 이 표본에서는 정확도도 떨어지지 않았다. 다만 26문장이라 정확도 차이(19·20·22)는 우연일 수 있다
- **무음 350ms 의 위험은 이 측정으로 알 수 없다**: 합성 음성은 문장 중간에 쉬지 않는다. 사람은 말 중간에 0.3–0.5초 자주 쉬어서, 350ms 면 한 문장이 둘로 잘려 번역될 수 있다 → 실기기에서 사람 목소리로 확인한 뒤 바꿀 것
- 추론 minimal(`TRANSLATION_REASONING=minimal`)은 문장이 잘리는 위험과 무관해 먼저 바꿀 수 있다
- **동시 통화 수 한계 (새로 알게 된 것)**: 통화 1건 = 번역 세션 2 + 전사 세션 2. 동시에 스트림 6개(통화 3건)에서 한도에 걸렸다. 시연(통화 1건)에는 문제없지만, 여러 통화를 동시에 하려면 OpenAI 사용 등급(tier)·한도 확인이 필요하다. 실패한 응답의 이유를 로그에 남기도록 엔진을 고치면 확인할 수 있다
- 결과 파일: `server/stream-measure-output/field-accuracy-{A-base,B-vad350,C-vad350-min}-{vi,zh}-*.jsonl` (git 제외)

**적용 (2026-10-24 사용자 결정)**: 기본값을 C 로 바꿨다 — `STREAM_VAD_SILENCE_MS=350`, `TRANSLATION_REASONING=minimal` (`server/src/config/env.ts` 기본값, `server/.env.example`, `deploy/render-env.sh`). 추론 강도는 문장 단위 통역에도 적용된다. 남은 확인: 실기기에서 사람 목소리로 말 중간 쉼에 문장이 잘리는지 — 잘리면 `STREAM_VAD_SILENCE_MS` 만 400–500 으로 되돌린다 (코드 변경 없음)

## 9. 새 설정으로 400문장 재측정 (2026-10-24, $4.74)

같은 400문장을 7절 데이터 보강 + 8절 C 설정(무음 350ms·추론 minimal)으로 다시 돌렸다 (`--label v2`, 비용 한도로 한 번 멈춰 `--label v2b --from` 으로 이어 돌림). 문장별 결과·틀린 이유: [`field-accuracy-results-v2.csv`](field-accuracy-results-v2.csv). 채점 기준은 2절과 같다.

| | 1차 (무음 500ms·추론 low) | 2차 (무음 350ms·추론 minimal·데이터 보강) |
|---|---|---|
| **정확도 전체** | **89.5%** (358/400) | **87.75%** (351/400) |
| ㄴ 은어 vi / zh | 89% / 91% | 85% / 86% ↓ |
| ㄴ 표준 용어 vi / zh | 86.7% / 88.3% | 91.7% / 88.3% |
| ㄴ 숫자·지시 vi / zh | 92.5% / 90.0% | 90.0% / 90.0% |
| **지연 중앙값** vi / zh / 전체 | 2.01 / 1.83 / **1.91초** | 1.74 / 1.48 / **1.60초** |
| 지연 90% 값 전체 | 2.39초 | **1.99초** |
| 2초 안 / 3초 안 | 62% / 97% | **90% / 99%** |
| 문장당 비용 | $0.0095 | $0.0118 (용어집이 길어짐) |

- **지연은 약 0.3초 줄었다** (중앙값 1.91 → 1.60초, 90% 값 2.39 → 1.99초). 5초 넘는 문장도 없어졌다 (최대 3.3초)
- **표준 용어는 보강 효과가 있다**: 훅 해지장치·고압선·화기 작업·비계 해체(vi), 슬래브 → 楼板·가불 → 预支工资(zh) 가 맞게 됐다
- **은어는 4–5%p 떨어졌다**: "스페아 있어?" → 엉뚱한 지시, 쓰루하시 → 깨진 글자, 사부로꾸 → 음역처럼 뜻을 짐작하지 않고 엉뚱하게 옮긴 경우가 늘었다. 추론을 minimal 로 낮춘 영향으로 보인다 (이 측정만으로 무음·추론·데이터 중 무엇 때문인지 가를 수는 없다)
- 새 데이터의 부작용 1건: zh "추락 방지망" → 防落物网(낙하물 방지망) — 새로 넣은 비슷한 용어와 섞임
- 여전히 틀리는 것: 슬래브 → 슬리브(받아쓰기부터 슬리브, vi), "퇴근은" → "최근엔"(받아쓰기), "세 시 반" → 3시, "이 볼트" → 볼트 2개
