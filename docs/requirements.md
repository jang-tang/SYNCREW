# 요구사항 명세 (MVP)

> 상태: 계획 v3 (2026-10-10). Phase 1 구현 완료, 검토 대기.
> 근거: 발표 PDF(`싱크필드_20260909 최종본.pdf`), 기존 저장소 `jecool0523/workplace-translation-mvp`, 2026-10-10 사용자 결정사항.

## 1. 서비스 목적

외국인 작업자와 관리자가 현장에서 언어 장벽 없이 소통하도록, 안전모 부착 모듈(일반 블루투스 헤드셋)과 휴대폰 앱을 통해 **현장 용어 특화 AI 실시간 통역**을 제공한다.

- 해결 문제(PDF 2–3쪽): 의사소통 문제(52.1%), 작업 지시 오해로 인한 생산 차질(63.9%), 초기 생산성 격차, 이주노동자 산업재해 증가.
- 사용성 전제(PDF 4–7쪽): 양손 자유, 소음 환경, 골전도 출력.

## 2. 확정된 결정사항 (2026-10-10)

| 항목 | 결정 |
|---|---|
| UI | 기존 PoC UI는 사용하지 않고 **새로 제작** |
| 실시간 통신 | WebSocket(Socket.IO) 기반 **1:1, 1:N, N:N** 모두 신규 구현 |
| 노이즈 필터링 | 다른 개발자가 제공. **교체 가능한 함수(플러그인) 인터페이스**만 제공 |
| 데이터 보존 정책 | 다른 개발자가 제공. **교체 가능한 정책 훅**만 제공 |
| 번역 모델 | **`gpt-realtime-2`** (OpenAI Realtime API) 사용 |
| 도메인 | 제조업 데이터 그대로 진행해도 무방 |
| 현장 특화 처리 | **로직만 구현**. 데이터셋은 이후 교체 가능하도록 어댑터 구조 |
| 인증 / 비밀번호 재설정 | **Supabase Auth** (이메일 + 비밀번호. 이메일 없는 작업자 대응은 하지 않음) |
| 계층 구조 | **현장(Room) - 관리자 / 구성원** 2단계 (조직 계층 없음) |
| 지원 언어 | 한국어(ko) + **중국어(zh), 베트남어(vi), 우즈베크어(uz), 러시아어(ru)** |
| 작업자 응답 | 1:1에서는 관리자와 구성원이 **동일한 흐름**(양방향 대칭) |
| 헬멧 모듈 연결 | **일반 블루투스 헤드셋** 방식 (OS 오디오 라우팅 사용) |
| 구독·결제 | 구현하지 않음 |
| 긴급 문장 원탭 전송 | **제외** |
| 범위 | MVP 필수 기능 중심 |
| 서버 호스팅 | **로컬** (개발자 PC에서 서버·DB 실행, 휴대폰은 같은 Wi-Fi로 접속) |
| OpenAI API 키 | 사용자가 서버 `.env`에 직접 입력 (`npm run setup:openai`) |
| OpenAI 비용 한도 | **$5** (기본 월 단위). 넘는 호출은 서버가 거부 |
| 위험도 감지 | **제외** |
| 폴더 구조 | `frontend/`(앱), `server/`(서버) 2개 |

## 3. 사용자와 역할

| 역할 | 범위 | 권한 |
|---|---|---|
| 관리자 (manager) | 현장 단위 | 현장 생성·설정, 가입 코드 발급, 가입 승인/거절/제외, 구성원 언어 수정, 1:1 대화, 그룹 대화, 일괄 지시 발송 및 상태 조회 |
| 구성원 (member) | 현장 단위 | 현장 가입 요청, 본인 언어 설정, 1:1 대화, 그룹 대화, 지시 수신·확인·완료 응답 |

- 역할은 **현장 멤버십 단위**로 부여된다. 같은 사용자가 현장 A에서는 관리자, 현장 B에서는 구성원일 수 있다.
- 현장을 생성한 사용자가 그 현장의 관리자가 된다. 한 사용자는 여러 현장을 만들거나 가입할 수 있다.
- 멤버십이 없거나 `active`가 아닌 사용자는 해당 현장 데이터에 접근할 수 없다.

## 4. 통신 모드

| 모드 | 설명 | 발신자 | 수신자 |
|---|---|---|---|
| 1:1 대화 (direct) | 두 사람이 서로의 언어로 대화 (PDF 20쪽) | 양쪽 모두 | 상대방 1명 |
| N:N 그룹 대화 (group) | 현장 단위 그룹 채널. 누구나 말하면 나머지 전원이 각자 언어로 수신 | 참여자 전원 | 나머지 참여자 |
| 1:N 일괄 지시 (instruction) | 관리자가 현장 전체 또는 선택한 구성원에게 작업 지시 (PDF 21쪽). 확인·완료 상태 추적 | 관리자 | 선택 대상 |

세 모드는 모두 같은 **메시지 팬아웃 파이프라인**(대상 언어별 1회 번역 → 수신자별 전달 상태 관리)을 공유한다.

## 5. 통역 파이프라인 요구사항 (PDF 22쪽)

```
음성 입력 → [노이즈 필터 플러그인] → STT → 현장 언어 특화 처리(용어 감지 → 용어 자동 보정)
        → gpt-realtime-2 번역(텍스트 + 음성 출력) → 수신자 단말 재생
```

- 텍스트 입력은 STT를 건너뛴다.
- 현장 특화 처리는 **데이터셋 어댑터**를 통해 데이터를 읽는다. 기존 저장소 데이터셋을 기본 샘플 어댑터로 제공한다.
- 번역 결과는 텍스트와 음성을 함께 저장·전달한다. 음성 재생이 실패하면 기기 TTS로 대체한다.
- 원문(STT 결과), 보정된 원문, 번역문을 모두 기록해 이후 검수에 사용할 수 있게 한다.
- 모든 OpenAI 호출은 비용 한도(BudgetGuard)를 거친다. 호출 전 예상 비용을 예약하고, 한도를 넘으면 호출하지 않고 실패 처리한다.

## 6. 기능 목록

### 6-1. MVP 필수

| # | 기능 | 비고 |
|---|---|---|
| F1 | Supabase 회원가입 / 로그인 / 로그아웃 / 비밀번호 재설정 | 이메일 + 비밀번호 |
| F2 | 프로필: 표시 이름, 기본 언어, 음성 재생 설정 | |
| F3 | 현장 생성 / 목록 / 기본 정보 수정 | 생성자 = 관리자 |
| F4 | 가입 코드 발급·폐기, 같은 코드를 담은 QR 표시 | |
| F5 | 가입 코드(직접 입력 또는 QR 스캔)로 가입 요청 → 관리자 승인 / 거절 | |
| F6 | 구성원 목록, 구성원 언어 확인·수정, 구성원 제외 | 제외 시 즉시 실시간 차단 |
| F7 | 1:1 대화: 음성 또는 텍스트, 양방향 통역, 자동 음성 재생, 다시 듣기 | |
| F8 | N:N 현장 그룹 대화 | 현장당 기본 그룹 1개 |
| F9 | 1:N 일괄 지시: 대상 선택(전체 / 선택), 언어별 번역, 수신자별 상태 | |
| F10 | 지시 수신 확인(ack) 및 작업 완료 응답 | |
| F11 | 메시지 상태: 처리 중 / 완료 / 실패, 실패 재시도 | |
| F12 | 재접속 시 누락 메시지·지시 동기화 | 앱이 꺼져 있던 동안의 데이터는 재실행 시 조회 |
| F13 | 노이즈 필터 플러그인 인터페이스 | 기본값: 통과(passthrough) |
| F14 | 데이터 보존 정책 훅 | 기본값: 아무것도 삭제하지 않음 |
| F15 | 현장 특화 처리 로직 + 데이터셋 어댑터 | 기본 어댑터: 기존 저장소 데이터 |
| F16 | 연결 상태 표시 및 오류 표시 | |
| F17 | OpenAI 비용 한도 ($5) | 사용량 DB 기록, 한도 초과 시 거부 |

### 6-2. MVP 제외 (추후)

푸시 알림(앱 종료 상태 수신), 작업조 단위 지시, 다중 관리자 지정 UI, 용어집 편집 화면, 감사 로그 화면, 구독·결제, 헬멧 전용 버튼·펌웨어 연동, Realtime 세션 상시 유지(지연 최적화), iOS 배포.

## 7. 비기능 요구사항

| 항목 | 요구 |
|---|---|
| 플랫폼 | Android 우선 (iOS는 코드 호환성만 유지) |
| 보안 | OpenAI 키는 서버 `.env`에만 보관. 모든 현장 데이터 접근은 서버에서 멤버십 검증 |
| 지연 | 음성 종료 → 수신자 재생 시작까지 목표 3초 이내 (측정 후 조정, 미검증 목표치) |
| 안정성 | 네트워크 단절 후 재접속 시 누락 없는 동기화, 중복 전송 방지 |
| 가독성 | 큰 버튼(최소 56dp), 원문과 번역문 동시 표시, 상태 배지 상시 표시 |
